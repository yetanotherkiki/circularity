/ circularity @ skullspace / proposal kit

circularity proposal kit

a reusable prompt + templates for bringing this proposal to your own hackerspace

what this is

a reusable kit for proposing a circularity / right-to-repair events subcommittee at your local hackerspace or makerspace. the original was developed for skullspace in winnipeg and shared publicly so other spaces can adapt it.

this is opinionated. it assumes a tested structure (why → what → events → ask → safety) and leans toward a terminal-aesthetic visual style by default. you can override either.

how it works

  1. read through the kit once so you know what you're getting into.
  2. answer the interview questions in step 1, locally and honestly.
  3. copy the prompt from step 2 and paste it into claude (or another capable model), filling in your answers from step 1 where the placeholders are.
  4. iterate on the output. push back on vague claims, swap statistics, refine the voice.
  5. generate the printable handout + supporting site (step 4) using the templates linked at the bottom.
  6. print, present, follow up.

step 1 — interview yourself

the model is only as good as the context you give it. answer specifically. if you don't know an answer, mark it [uncertain] rather than guessing — claude can flag those for you to verify later.

about you

  • name / pseudonym you use at the space
  • your role / how long a member
  • proposing solo or with co-conspirators

about your space

  • name + city + country
  • approximate active member count
  • existing committees / formal structures
  • meeting format (general assembly w/ vote, board-driven, informal)
  • how new initiatives typically get approved (motion, vote, signup, etc.)
  • existing tools and workspace relevant to this proposal

about your local waste context

  • which waste streams are most visible / urgent locally (e-waste, textiles, plastics, food, batteries, etc.)
  • any local stats on waste volumes — cite source, even if rough
  • existing recycling / diversion infrastructure (municipal programs, certified depots, etc.)

about your legal context

  • right-to-repair laws (national, provincial/state, with bill numbers and dates if you have them)
  • extended producer responsibility (EPR) programs
  • any restrictions or licensing for handling specific waste types
  • recent legislative activity worth citing

about local partner orgs

  • e-waste refurbishers / depots (name + 1-line description + URL)
  • repair cafés / tool libraries
  • thrift / textile diversion orgs
  • educational institutions or NGOs that might partner
  • any indigenous-led or community-rooted orgs in this space

about events you'd run

  • low-effort starting points (drop-offs, swaps, etc.)
  • hands-on programming you'd want eventually (repair nights, workshops)
  • safety / compliance constraints unique to your space

about the ask

  • what you specifically need from membership (committee members, budget, storage, process clarity)
  • approximate budget range you're considering
  • timeline (start when, scale when)

about voice + aesthetic

  • voice (formal, casual, tongue-in-cheek, all-lowercase, etc.)
  • aesthetic (terminal-phrack / zine-print / corporate-clean / something else)
  • format (1-page sheet, 2-page handout, longer)

step 3 — refine the output

first-shot output is rarely print-ready. things to push back on:

  • vague statistics. if claude says "studies show...", ask for the specific source. drop or swap claims that can't be substantiated.
  • generic framing. if the WHY section reads like it could be about anywhere, push it harder toward your local context.
  • boilerplate ask. make sure THE ASK matches what your space's process actually requires.
  • over-claiming partnerships. the proposal should flag that partner orgs haven't been contacted yet (unless you have).
  • AI-shaped prose. watch for "Moreover", "Furthermore", excessive em-dashes, ChatGPT-style bullet lists where prose would work better. ask for a rewrite in a more natural register.
// pro tip

tell claude to flag every claim with a confidence rating (well-sourced / estimated / unverified) at the bottom of the document. this makes it much easier to catch fabrications and lets you decide what to remove vs. verify.

step 4 — deploy the supporting site

the live site provides references and further reading that don't fit on the printed handout, accessed via a QR code on the PDF. github pages is the easiest free hosting option.

  1. create a new public github repo. suggested name: short, descriptive, lowercase. circularity or repair-proposal works.
  2. push the following files to the main branch:
    • index.html — the site itself
    • your-proposal-name.pdf — the printable handout, so the site can link to it
    • .nojekyll — empty file. tells github pages to skip jekyll processing.
    • LICENSE — CC BY-SA 4.0 recommended, to match this kit
    • README.md — brief description for visitors who land on the repo
  3. repo settings → pages → source: pick "deploy from a branch", branch main, folder / (root). save.
  4. wait ~1–2 minutes. your URL will be https://YOUR-USER.github.io/REPO-NAME/.

step 5 — generate and embed your QR code

  1. pick any QR generator. qr-code-generator.com works in browser; the python qrcode library works programmatically. encode your full deployed site URL including https://.
  2. save as PNG (or jpeg). aim for at least 256×256 px so it stays crisp at print size.
  3. drop the file into the same dir as render.py (the PDF generator), update the QR_PATH constant to point at it, re-run render.py.
  4. test the QR by scanning it from a printed copy (not just the screen) before printing 50.

step 6 — present at the meeting

a few things that worked at skullspace:

  • print 30–50 copies. ~$5–10 at any copy shop, library, or member's home printer.
  • lead with the WHY, not the WHAT. concrete waste numbers + the recent legal context get attention. abstract framing doesn't.
  • spend the most time on THE ASK. members want to know what they're being asked to commit.
  • keep the email signup sheet visible and pass it around proactively. don't make people ask.
  • have answers ready for obvious objections (cost, liability, storage, member capacity).
  • don't push for a vote on day one if you can avoid it. use the first meeting to gauge interest and answer questions. schedule a follow-up.

faq / troubleshooting

"the site doesn't show any styling"

  • hard-refresh your browser (cmd-shift-R / ctrl-F5).
  • confirm .nojekyll is in the repo root and was actually pushed (some git tools skip dotfiles).
  • check that your index.html doesn't start with --- — that triggers jekyll's YAML frontmatter parser.
  • try in an incognito window to rule out browser cache.

"the QR code doesn't scan"

  • verify the encoded URL is correct using any decoder.
  • print at least 1.5"×1.5" — smaller and phones struggle.
  • increase the QR's error correction level (H) if you've got space; tolerates more print noise.
  • test from a printed copy before the meeting, not from your screen.

"the PDF doesn't fit on 2 pages"

  • trim the WHY section first — usually the most padded.
  • reduce email signup grid rows.
  • tighten THE ASK descriptions.
  • last resort: make it 3 pages instead.

"members aren't engaging at the meeting"

  • don't lead with abstract numbers. lead with a concrete local story or a recent waste-related event.
  • have low-friction commitments ready (sign up to receive updates, not "commit 5 hours/week today").
  • read the room. if energy is low, defer to a follow-up.

"the proposal got rejected"

  • ask specifically what concerns the membership has. address them and bring it back.
  • find a smaller first step to demonstrate value (a single one-off event, a bin in the corner).
  • consider partnering with an existing committee instead of forming a new one.

"people are skeptical of the right-to-repair / sustainability framing"

  • reframe in terms of member benefit: skill-share, free access to tools, community.
  • lead with the practical (broken phones, dead laptops piling up) rather than the political.
  • the legal context helps here: laws have shifted, this is now mainstream, not fringe.

"claude is producing AI-shaped prose i don't want"

  • be explicit about voice in your prompt: "no Moreover / Furthermore / em-dashes / excessive bolding".
  • provide a sample paragraph in your own voice and ask claude to match the register.
  • if the output still feels off, ask for a "tightening pass" with specific targets (cut adjectives, shorten sentences, etc.).
